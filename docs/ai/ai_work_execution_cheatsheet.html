AIと仕事を進める.

曖昧でも止まらない。勝手にも進まない。

調べてから聞く。考えてから返す。進めてから止まる。確認してから完了と言う。

チャット形式でAIと業務を進めると、曖昧な依頼、質問返し、途中停止、未確認の完了報告、判断材料不足が起きやすい。長い運用ルールを書く前に、困り方に合わせて短い追加指示を差し込む。

01

よくある6パターン

PATTERNS

全部を毎回入れなくていい。いま困っている挙動に近いものを1〜2個足す。

AMBIGUOUS REQUEST

指示・要件が曖昧

依頼が曖昧でも、会話や既存情報から目的・前提・完了条件を推定し、合理的な仮定を置いて進めてください。
推定では進められない重要な判断だけ、人間に確認してください。
QUESTION LOOP

AIがすぐ人に質問を返す

質問する前に、自分で調査・確認・比較・検討できることを完了し、可能なら推奨案まで作ってください。
人間には、調査しても解消できない判断や権限・リスクに関する事項だけを返してください。
STOPS TOO EARLY

途中で止まる・ゴールまで進まない

調査・説明・計画を作ること自体を完了とせず、実行可能な次の工程があればゴールまで継続してください。
安全に進められなくなった時だけ、止まった理由と再開に必要な条件を示してください。
FALSE COMPLETION

やっていないのに完了報告する

生成・依頼・実行・確認・反映を区別し、実際に確認できていないことを「完了」「対応済み」と報告しないでください。
完了を報告する前に、要求された成果と完了条件を満たした証拠を確認してください。
FRAGMENTED REPORT

報告が断片的で判断できない

人へ判断を求める場合は、事実・未確認事項・選択肢・影響・推奨案を整理し、何を判断すればよいか明確にしてください。
人間がもう一度調査し直さないと判断できない状態で、単に「どうしますか」と返さないでください。
AUTONOMY BOUNDARY

勝手に進める／何でも聞く

可逆で低リスクな実務判断はAI側で進め、不可逆・高影響・権限・リスク受容に関わる判断だけ人間に確認してください。
「迷ったら全部聞く」でも「全部勝手に進める」でもなく、判断の影響度で境界を決めてください。
02

まとめて入れるなら

MINIMUM SET

長文の運用規約ではなく、まずはこの短い原則でも効く。

調べてから聞く。考えてから返す。進めてから止まる。確認してから完了と言う。
低リスクな判断は自分で進め、人にしか決められないことだけ、判断できる材料を揃えて確認してください。
03

どこに入れる?

USE

一度きりの依頼より、繰り返し同じ失敗が起きる場所へ置くと効く。

チャットの追加指示その場で起きている困り方に対応する1〜2項目だけ追加。
プロジェクト共通指示毎回同じ進め方を求めるなら、プロジェクトの恒常ルールへ。
Agent / Workflow実行・確認・人間判断の境界が固定化できたら、プロンプトだけでなく処理フローへ。
注意：「質問しないで」「勝手に進めて」だけでは危険。質問前の調査と、人間に戻す条件をセットで決める。
THE POINT
人に返すのは、
未完成の思考ではなく、判断。

AIが自分で減らせる不確実性はAIが減らす。人は、目的・責任・高影響な判断に集中する。
